실제 Q1ASM 예제 · 타임라인 클릭 · VS Code 선택 범위. 자동 검증 결과와 직접 확인할 기준을 함께 담았습니다.

검증 예제

직접 확인하는 순서

  1. VS Code의 File → Open Workspace from File…에서 검증 workspace를 엽니다. 링크가 JSON으로 열리면 이 경로를 사용하세요. 확장이 이미 열려 있었다면 Developer: Reload Window를 한 번 실행합니다.
  2. 왼쪽 예제를 고르고, 표시된 program.q1asm을 VS Code에서 엽니다. Q1Lens: Open Timeline Preview를 실행합니다. 프로젝트를 묻는 경우 해당 예제의 q1timeline.yml을 고릅니다.
  3. Analysis는 처음 표시되는 분석 화면입니다. Playback은 위쪽 ▶ 아이콘(툴팁 Run execution)을 누른 후 확인합니다. 무한 반복은 잠시 실행한 뒤 Ⅱ 아이콘(Pause execution)으로 멈춥니다. 수동 실행은 시간·명령 수 제한으로 멈출 수도 있습니다. Analysis로 돌아갈 때는 ↻ Refresh를 누릅니다.
  4. 타임라인 위의 반복 범위(×N 또는 forever)를 누릅니다. 아래의 파란 줄 범위와 실제 코드 선택이 일치하는지 확인합니다. 중첩 루프는 바깥 반복을 펼친 뒤 안쪽 범위를 누를 수 있습니다. 12번처럼 RT 시간이 0인 반복은 상단의 Instruction 보기를 사용합니다.
  5. 루프 시작 라벨과 마지막 반복 명령까지 포함되는지, 타임라인 시간 커서가 선택 때문에 다시 이동하지 않는지 확인합니다. Q1 core의 개별 명령은 블록 아래쪽을 누르면 해당 위치로 이동합니다. 블록 위쪽의 작은 분기 버튼은 경로 선택 메뉴를 엽니다.

리포트의 소스 링크는 원문을 보여줍니다. VS Code에서 열 때는 옆의 경로 복사를 사용해 Ctrl+P에 붙여 넣으세요. 직접 확인 체크는 이 브라우저에만 저장됩니다.

판정 규칙과 현재 한계

루프 영역으로 확인된 이벤트를 기준으로 선택하며, 명령 이름이 loop인지 검사하지 않습니다. 정적 분석은 일부 조건부·간접 점프를 루프로 요약하지 못합니다. 실행 기록에서 반복 경로가 확인되면 같은 전체 선택이 적용됩니다. 목적지가 불명확한 점프와 일반 순방향 점프는 한 점 이동을 유지합니다.

반복 경로의 코드가 물리적으로 떨어져 있으면, 소속 명령을 모두 포함하는 처음 줄부터 마지막 줄까지 하나의 연속 범위로 선택합니다. 따라서 그 사이의 실행되지 않은 코드도 선택에 포함될 수 있습니다. 초기 카운터 설정은 통상 범위 밖이지만, 떨어진 경로 사이에 놓여 있다면 포함됩니다.

자동 검증은 분석 결과, 실제 웹뷰 클릭 메시지, 실제 VS Code 편집기 API를 나누어 검사합니다. 아래 수치는 실제 하드웨어 실행이나 모든 가능한 제어 흐름에 대한 증명을 뜻하지 않습니다.

검증에서 발견하고 수정한 중첩 루프 표시 문제

안쪽·바깥쪽 반복 표시가 같은 높이에 겹쳐, 한쪽 범위를 마우스로 누를 수 없는 경우가 발견됐습니다. 겹치는 범위를 서로 다른 높이에 배치하고 그 아래의 명령 블록 공간을 확보하도록 수정했습니다. 소스 선택 범위는 그대로 유지됩니다.
